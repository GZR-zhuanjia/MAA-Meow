# 定时多 Profile 任务链实施计划

## 实施约束
- 尽可能最小化修改，优先复用现有组件与生命周期；不重构、不引入新框架，只做必要编译和少量针对性测试。

## 目标与行为
- 在定时策略中增加「单配置 / 任务链」执行模式，与固定时间、间隔周期正交。
- 任务链保存有序 Profile ID，界面可添加、移除、上移、下移；至少两个不同配置。旧策略默认单配置，无需迁移。
- 一个 Profile 的实际任务正常结束后才启动下一个。失败、配置失效、手动停止、掉线中止和运行时长限制终止整链，不继续切号。
- 每个 Profile 使用自己的任务配置。切号由其「启动游戏」任务及账号设置完成；查看现有启动游戏实现后给出准确提示，不凭空保证重启能力。
- 同一条链只执行一次初始倒计时/唤醒流程；自动熄屏、关闭游戏、退出应用等策略收尾在整链结束时执行。全局关闭游戏逻辑也必须避免在中间轮次关闭新启动的游戏。

## 具体工作
1. 检查仓库约定与相关测试。涉及 ScheduleStrategy、ScheduleEditViewModel/View、ScheduleListView、ScheduleTriggerHandler、LaunchIntentMapper、LaunchModels、LaunchPipeline、StartTaskChainUseCase、TaskEndRegistry、TaskChainState。沿调用链核实配置切换、停止和终态行为。
2. 在 ScheduleStrategy 增加带默认值的执行模式和有序配置列表，保留 profileId 兼容旧配置及旧调用。提供统一有效配置序列，避免 UI、验证和运行端各自解释。新建、编辑、序列化往返均保存顺序。
3. 编辑界面增加执行模式与有序选择控件；显示缺失配置而非静默删除，保存时验证链长度、重复、配置存在。列表展示模式和顺序。补齐现有语言资源，简洁说明每个账号需配置启动游戏。
4. 将执行序列穿过定时触发与 LaunchRequest/Intent 映射，外部单配置启动保持兼容。运行前及每轮开始验证目标存在、启用任务不为空，失败写明配置与原因。
5. 在现有执行协调层实现串行运行生命周期，使用真实终态事件，不用时间延迟猜测结束。注意 TaskEndRegistry NATURAL 也包含 ERROR，必须结合执行状态判断成功。快速完成、旁路任务无 Core、注册回调时已结束均不可丢事件。
6. 保持整链的运行所有权，处理手动启动、forceStart 抢占、取消和新定时触发；旧链回调不能影响新运行。审查 armOnce 单槽覆盖、全局关游戏 dispatch 顺序，保证上一轮清理完成后才启动下一轮。必要时扩展最小生命周期接口，不全面重构。
7. 整链终止时释放资源并收尾；中间轮次不退出应用、不关闭屏保、不自动熄屏。日志包含当前配置和进度。旧单配置行为不变。
8. 添加简短使用文档。只运行必要验证：优先相关 Kotlin 编译，以及少量覆盖序列持久化/验证、正常串行、停止/错误不继续的聚焦测试；不跑全量 Android/设备测试。缺少 SDK/依赖时准确记录限制，不花大量时间搭环境。
9. 检查 diff，提交功能和计划到独立分支 feat/scheduled-profile-chain，目标 fork 为 GZR-zhuanjia/MAA-Meow。不得向 aliothmoon 上游推送，不强推、不自动合并。

## 交付检查
- 单配置旧策略仍能加载、编辑和启动。
- A → B → C 只在前一配置真正完成后推进，停止/异常不推进。
- 最终收尾只发生在整链末尾；快速完成与并发抢占不会产生旧回调串扰。
- 报告实际完成的验证、无法验证的设备切号行为和提交地址。
